# Не по припеву

Личный музыкальный квиз со статистикой и отдельными гостевыми ссылками.

## Как устроено

- `/` — личная коллекция и статистика, закрытые паролем в Nginx.
- `/g/<случайный-токен>` — публичное прохождение одного квиза по длинной непредсказуемой ссылке.
- `/g/track-info` — публичная read-only справка для карточек результатов гостя; приватные результаты и статистика через неё не выдаются.
- `/catalog` — личная рабочая страница общей базы: поиск, годы, источники, готовность и повторы исполнителей.
- Гостевые результаты рассчитываются в браузере и не сохраняются.
- После прохождения гость видит сравнение своих баллов с последним результатом владельца и может исправить собственные баллы или аннулировать вопрос; гостевые правки остаются в его текущей сессии.
- На итоговом экране год и доступная справка о песне, альбоме и исполнителе показываются сразу, без отдельного раскрытия карточки.
- Отмеченные владельцем плохие фрагменты временно исключаются из гостевого квиза и сравнения; после исправления отрезка возвращаются автоматически.
- Личные результаты хранятся в SQLite на сервере.
- Изменение баллов отображается мгновенно и синхронизируется в фоне.
- В результатах можно отметить плохой фрагмент и снять отметку повторным нажатием.
- Во время прослушивания видны прошедшее и оставшееся время фрагмента.
- В раскрытой карточке результата сайт ищет год и релиз в MusicBrainz и сохраняет ответ в локальный кэш на 90 дней.
- `/g/feedback` отдаёт только агрегированные ошибки и актуальные отметки фрагментов без ответов, результатов и идентификаторов прохождений. После изменения ролика или секунд старая отметка автоматически считается обработанной.

## Локальная разработка

```bash
npm ci
npm run dev
```

База по умолчанию создаётся в `data/quiz.sqlite`. Другой путь можно задать через `QUIZ_DB_PATH`.

## Сборка

```bash
npm run build
```

Проект собирается как автономное Next.js-приложение.

## Импорт песен из разобранных квизов

Ответы первого формата из `results/all-answers.csv` и нового формата из
`results/new-quizzes/music-answers-final.csv` объединяются в отдельный пул:

```bash
npm run import:quiz-answers
npm run fetch:quiz-answer-artists
npm run enrich:quiz-answer-yandex
npm run build:song-database
```

Импорт исключает пары, уже присутствующие в общей базе, и повторы внутри нового
набора. Для ответов только с исполнителем Яндекс Музыка подбирает одну новую
песню: у популярных артистов пропускаются первые три позиции, у менее известных
берётся верхняя подходящая. Первый формат получает сложность `middle`, новый —
`deep`, если на обложке или в названии раунда не указано иное. Неоднозначные
имена сохраняются в `data/quiz-answer-unresolved-artists.csv` и автоматически в
квиз не проходят.

## Официальные статусы публикации

Публичная готовность больше не равна наличию ссылки на YouTube. Для каждой песни отдельно фиксируются проверки личности исполнителя, первого года и звучащей версии, обложки или архивного материала, фото, ролика, фрагмента, связей людей с проектами, сложности, авторов и OST. Допустимые состояния: `missing`, `automatic`, `verified`, `failed`, `stale`, `not-applicable`.

Из них вычисляется жизненный цикл: `catalogued` → `enriched` → `technical-ready` → `selected` → `verified` → `published`; спорные записи переходят в `quarantined` или `rejected`. Источник истины — `data/song-publication-verification.json`, а не общий ручной флаг.

```bash
node scripts/build-new-rules-test-release.mjs
node scripts/verify-new-rules-test-release.mjs
node scripts/generate-next-quiz.mjs --strict-publication
```

Строгий генератор учитывает `conflictEntityIds`: сольный музыкант и его заметный проект не попадут в один квиз. Предрелизная проверка останавливает выпуск при повторе песни или ролика и при недоступном видео.

## Сервер

Первичную установку выполняет `deploy/bootstrap.sh`. Она создаёт отдельную службу, Nginx-конфигурацию, пароль для личной части, ежедневные резервные копии и проверку обновлений GitHub каждые пять минут.

После первой установки новые коммиты в `main` публикуются автоматически. Неудачная сборка не заменяет работающую версию.
