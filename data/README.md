# База кандидатов для квизов

`song-pool.json`, `song-pool-2.json` и `song-pool-3.json` — три тысячи пар «исполнитель — песня» для будущих выпусков. Это кандидаты, а не готовые карточки: YouTube-клип, фактический год релиза, форма исполнителя и границы фрагмента проверяются непосредственно при сборке квиза.

`chart-songs-spotify-ru.json` — отдельный каталог всех 2 967 уникальных записей из доступного агрегата дневного Spotify-чарта России за 2020-07-15…2022-04-07. Он включает и зарубежные песни: поле `isLocalCandidate` отмечает русскоязычные и локальные записи, пригодные для основной тематики квиза. Поле `alreadyInSongPool` позволяет отличить уже сохранённые пары.

`chart-songs-europa-plus.json` — 816 уникальных песен из 820 позиций ежегодных чартов «Европы Плюс» за 2007–2025 годы. Повторные попадания одной песни по годам объединяются и повышают `annualAppearanceWeight`. У 39 старых записей источник не указал исполнителя; они сохранены с `artist: null` и `artistResolution: "missing"`, чтобы не подставлять догадку вместо данных.

`chart-songs-tophit-monthly.json` — индекс накопительной истории ежемесячного радиочарта TopHit; сами записи лежат в сжатом `chart-songs-tophit-monthly.json.gz`. Повторный импорт полной или дополненной выгрузки обновляет позиции тех же `track_id`, а не удваивает их. ISRC сохраняется, но участвует в автоматическом сопоставлении только тогда, когда код относится ровно к одному TopHit `track_id`: в старых страницах встречаются ошибочно повторённые коды и коды, приклеенные к полю правообладателя.

`chart-catalog.json` — индекс единого накопительного каталога, а полные записи лежат в сжатом `chart-catalog.json.gz`. Каталог склеивает исторические импорты и собственные снимки живых чартов, но сохраняет исходные варианты написания в `artistAliases` и `titleAliases`. Повторные попадания внутри одного источника суммируются, затем вклад каждого источника нормализуется и складывается в `combinedScore`.

`song-database.json` — индекс общей базы песен, объединяющей чартовый каталог, три пула кандидатов и уже опубликованные квизы. Полные записи находятся в `song-database.json.gz`, а первые 500 приоритетных сомнительных записей — в `song-database-review.json`. У каждой песни раздельно хранятся этап работы (`waiting`, `used`, `rejected`), язык, проверка личности записи и состояние фрагмента. Поэтому, например, иностранная песня сохраняется и не становится автоматически отклонённой.

В версии 2 база также хранит исполнительские сущности (`artistIds`), пересечение с уже звучавшими исполнителями, год первого релиза и год конкретной версии отдельно от годов чартов. Единственная дата TopHit сохраняется как кандидат года, но не становится подтверждённой без проверки. `readyForCuration` означает готовность к ручному отбору, `readyForUniqueArtistQuiz` — пригодность для выпуска без повторов исполнителей, а `readyForPublication` дополнительно требует подтверждённый год, ролик и проверенный фрагмент.

`quiz-candidates.json` — приоритетная очередь кандидатов без повторов исполнительских сущностей. Правила находятся в `quiz-generation-policy.json`; до квиза XXX любой участник разового фита считается использованным, а постоянная группа или дуэт остаётся одной сущностью.

`song-enrichment-overrides.json` — проверенные годы, версии, альбомы, формы исполнителей, фотографии, составы и факты. Он имеет приоритет над автоматически найденными кандидатами; спорные сведения остаются в очереди проверки.

`song-enrichment-auto.json` — постоянный результат пакетного сопоставления с MusicBrainz, Wikidata и Wikimedia Commons. Он хранит всех участников фитов, год первого релиза отдельно от года альбома, составы, короткие факты, лицензии фотографий, ссылки на источники и оценку уверенности. Неоднозначные совпадения автоматически не публикуются; пакет продолжает работу с места остановки.

`song-status-overrides.json` — ручные решения редактора. Они имеют приоритет над эвристиками языка и автоматически рассчитанными статусами. Здесь же можно сохранить вручную подтверждённый YouTube ID. Ключом служит `id` песни из `song-database` либо строка `normalizedArtist:normalizedTitle`; значение `externalIds.youtube` — массив из одного или нескольких 11-символьных ID роликов, без полного URL:

```json
{
  "version": 1,
  "songs": {
    "song-id-or-normalized-key": {
      "externalIds": {
        "youtube": ["AbCdEfGhI_1"]
      }
    }
  }
}
```

После `npm run build:song-database` эти значения попадают в `externalIds.youtube`, поэтому блокер `youtube-video` снимается. Само наличие ролика не означает, что выбранный отрывок был прослушан: `fragment-review` останется до отдельного ручного подтверждения `fragmentStatus: "good"`. Не выставляйте этот статус только на основании найденного ID. Неверный формат ID, полный YouTube URL или неподдерживаемое пространство идентификаторов останавливают сборку с понятной ошибкой.

`chart-observations.json` хранит сами снимки: ежедневно для Apple Music и Deezer, еженедельно для YouTube и Shazam. Повторный запуск в тот же период обновляет снимок, а не удваивает его. `artist-aliases.json` содержит ручные соответствия для вариантов вроде кириллицы и латиницы; сомнительные совпадения попадают в `chart-merge-review.json` для проверки.

Первый файл сильнее ориентирован на новых для квиза исполнителей. Во втором повторы исполнителей разрешены, но песни не пересекаются ни с первым файлом, ни с уже сыгранными карточками.

## Как использовать

1. Загрузить все файлы `data/song-pool*.json`, затем исключить точные песни, уже присутствующие в актуальном `app/quiz-data.ts`.
2. Исключить карточки, помеченные пользователем как плохой фрагмент.
3. Взять смесь `sourceBand`: меньше очевидных `recognizable`, больше `middle` и `deep`.
4. Проверить название и исполнителя минимум по двум источникам.
5. Найти устойчивый официальный ролик и подобрать фрагмент без произнесённого названия песни.

`listYear` и `listRank` относятся к редакционной подборке Lezza TV и не считаются подтверждённым годом релиза или официальной позицией в чарте. `goldenGramophoneYears`, если поле есть, служит только дополнительным независимым сигналом узнаваемости.

## Чартовый вес

Третий пул строится из дневного агрегата Spotify Russia. Дневной и недельный агрегаты одного чарта намеренно не складываются, чтобы не учитывать одно и то же попадание дважды.

`chartScore` приведён к шкале 0–100:

- 40% — логарифм числа дней в чарте;
- 25% — логарифм суммарных прослушиваний;
- 20% — доля дней в топ-10;
- 10% — сила пиковой позиции;
- 5% — доля дней на первом месте.

Сырые показатели (`appearancesDays`, `top10Days`, `numberOneDays`, `peakPosition`, `peakStreams`, `totalStreams`) сохраняются рядом, поэтому формулу можно менять без повторного ручного сбора.

## Источники

- [Lezza TV](https://www.youtube.com/@LEZZATV/videos) — основной широкий каталог ежегодных редакционных подборок.
- [Золотой граммофон](https://ru.wikipedia.org/wiki/Список_лауреатов_премии_«Золотой_граммофон») — независимая проверка части известных песен.
- [TopHit](https://tophit.com/chart/top/radio/hits/ru/annual) — ручная сверка радиочартов.
- [Песня года](https://ru.wikipedia.org/wiki/Песня_года) — дополнительный источник для старых и тематических выпусков.
- [Подборка музыкальных квизов](https://www.youtube.com/playlist?list=PL9vtHjwVXGU0syiRIYghW2A4_lT0UtaY1) — контроль ощущения сложности и узнаваемости.
- [Spotify Charts](https://charts.spotify.com/charts/overview/global) — исходный чарт; недельная методология описана в справке Spotify.
- [Kworb: Spotify Daily Chart — Russia](https://kworb.net/spotify/country/ru_daily_totals.html) — доступный агрегат повторных дневных попаданий за 2020–2022 годы.
- [Европа Плюс: ежегодные чарты](https://europaplus.ru/year-chart) — официальные годовые списки за 2007–2025 годы.
- [YouTube Russia на Kworb](https://kworb.net/youtube/insights/ru.html) — еженедельный российский топ.
- [Shazam Russia Top 200](https://www.shazam.com/ru-ru/charts/top-200/russia) — официальный текущий топ; автоматический снимок читается через его публичное представление на Kworb.
- [Apple Music RSS](https://rss.marketingtools.apple.com/) — официальный JSON текущего российского топа.
- [Deezer Russia на Kworb](https://kworb.net/charts/deezer/ru.html) — текущий российский топ.

`chart-sources.json` также фиксирует найденные, но пока не импортируемые источники. Top40-Charts и TopHit возвращают HTTP 403 серверному сборщику, поэтому защита не обходится: для них нужен разрешённый экспорт или другой официальный канал. Яндекс Музыка остаётся в списке наблюдения до появления стабильного публичного источника.

## Обновление чартового каталога

Сохранить HTML агрегата во временный файл и запустить:

```bash
node scripts/import-spotify-russia-chart.mjs /path/to/ru_daily_totals.html
```

Скрипт заново собирает `chart-songs-spotify-ru.json` и `song-pool-3.json`, исключает песни из первых двух пулов и текущих квизов и ограничивает одного нормализованного исполнителя двенадцатью позициями.

Для сохранённых JSON ежегодных чартов «Европы Плюс»:

```bash
node scripts/import-europa-plus-charts.mjs /path/to/year-json-directory
```

Для CSV или JSON, экспортированного браузерным сборщиком TopHit:

```bash
npm run import:tophit -- /path/to/tophit_monthly.csv
CHART_REBUILD_ONLY=1 npm run monitor:charts
```

Импорт можно повторять после добавления новых месяцев. Внутри TopHit строки сопоставляются по `track_id`; однозначный ISRC и нормализованные исполнитель с названием связывают их с другими источниками. Сомнительные ISRC-коллизии не склеиваются автоматически.

Для очередного снимка всех доступных живых чартов и пересборки единого каталога:

```bash
npm run monitor:charts
```

На GitHub этот запуск выполняется автоматически раз в сутки. Ошибка одного источника не мешает сохранить остальные; если недоступны все источники, задача завершается с ошибкой и не публикует пустой каталог.
